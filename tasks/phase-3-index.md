# Phase 3 — Index Generator

## Goal

Implement `tools/generate_index.py` that scans the repository, parses all
manifests and frontmatter, and produces `INDEX.md` — a human-readable index
with atoms, composites, recipes, and the inverse dependency graph. Wire it
into a pre-commit hook so it stays up to date automatically.

## Prerequisites

- Phases 1 and 2 complete and committed.
- You are on branch `bootstrap`.
- `pyproject.toml` exists at repo root.
- Canonical example content from Phase 1 is in place (used for testing the
  generator).

## Deliverables

### 1. `tools/generate_index.py`

A Python script that produces `INDEX.md` at the repo root.

#### CLI

```bash
uv run python tools/generate_index.py [--check]
```

- Without flags: regenerates `INDEX.md`.
- `--check`: exits non-zero if `INDEX.md` is out of date (compare freshly
  generated content with the on-disk version). Used in CI.

#### Logic

1. **Walk** these folders for atoms (parse frontmatter):
   - `prompts/library/*.md`
   - `prompts/templates/*.md`
   - `stack/*.md`
   - `skills/*/SKILL.md`
2. **Walk** these folders for composites (parse `manifest.yaml`):
   - `agents/*/manifest.yaml`
3. **Walk** these folders for recipes (parse `manifest.yaml`):
   - `workflows/*/manifest.yaml`
4. **Catalog** non-frontmatter atoms (by filename + optional companion `.md`):
   - `mcp-servers/*.json`
   - `tools/*.py`
   - `n8n-workflows/*.json`
5. **Build inverse dependency graph**: for each atom, list which composites
   and recipes reference it (via paths in `uses:`, `agents:`,
   `n8n_workflows:`).


#### Implementation notes

- Use `pydantic` models matching the schemas from `docs/schemas/`. Define the
  models in Python (do not dynamically generate them from YAML in this
  phase; that complexity is for later).
- Use `pyyaml` for YAML parsing.
- Use `typer` for the CLI.
- Use `rich` for human-friendly stdout output (progress messages, summary).
- Sort entries alphabetically within each section.
- All paths in the output are relative to repo root.
- **Idempotent**: running the script twice produces byte-identical output.
- **Robust** to missing optional fields. Only require fields marked required
  in the schema. Skip files that fail to parse and report them at the end
  (do not crash).
- For tables, truncate descriptions to ~60 characters with an ellipsis if
  longer.

#### Suggested module structure

A single file is fine for this version. Top-level functions:

```python
def discover_atoms(root: Path) -> dict[str, list[Atom]]:
    ...

def discover_composites(root: Path) -> list[Composite]:
    ...

def discover_recipes(root: Path) -> list[Recipe]:
    ...

def build_inverse_graph(atoms, composites, recipes) -> dict[str, list[str]]:
    ...

def render_index(atoms, composites, recipes, graph) -> str:
    ...

def main(check: bool = False) -> int:
    ...
```

The script should also expose `discover_*` and `build_inverse_graph` so
`tools/check.py` (Phase 4) can import them without duplication.

### 2. `.pre-commit-config.yaml`

Replace any existing placeholder with the following config:

```yaml
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: trailing-whitespace
      - id: end-of-file-fixer
      - id: check-yaml
      - id: check-json

  - repo: local
    hooks:
      - id: generate-index
        name: Regenerate INDEX.md
        entry: uv run python tools/generate_index.py
        language: system
        pass_filenames: false
        always_run: true
```

### 3. Install dependencies and pre-commit

Run these commands as part of executing this phase:

```bash
uv sync
uv run pre-commit install
```

These create `.venv/` (gitignored via the existing `.gitignore` patterns),
`uv.lock` (tracked), and install the git hook in `.git/hooks/pre-commit`.

`uv.lock` must be added to git (it is tracked).

### 4. Smoke test

After implementing, run:

```bash
uv run python tools/generate_index.py
cat INDEX.md  # confirm it contains example-hello-world and example-echo-agent
uv run python tools/generate_index.py --check  # must exit 0
```

If `--check` exits non-zero immediately after a fresh generation, the
generator is not idempotent. Fix it before committing.

## Commit

```bash
git add .

```

Note: the pre-commit hook will run on this very commit and may modify
`INDEX.md`. If it does, git will refuse the commit; just `git add INDEX.md`
and re-commit with the same message.
