# Auth + Database Setup

Skill di Phase 4 della methodology `/web-builder`. Branch logic complessa basata su scelte discovery (Q5 auth + Q6 database). Output: file integration scritti + lista env vars per utente.

## When to use

Attiva quando:
- Phase 3 (CLAUDE.md) completata (`config.build.claude_md_done == true`)
- `config.build.auth_db_done == false`
- `config.stack.auth != "none"` OR `config.stack.database != "none"`

```yaml
auth_provider: clerk | workos | supabase_auth | custom | none
db_provider: convex | supabase | sanity | none
project_path: /path/to/project
framework: nextjs_15 | astro | sveltekit
```

## Branch logic

### Branch 1 — Default (Clerk + Convex)

**Trigger**: `auth_provider == "clerk" AND db_provider == "convex"`

#### Step 1.1 — Install packages

```bash
cd <project_path>
npm install @clerk/nextjs convex
```

#### Step 1.2 — Init Convex

```bash
npx --yes convex dev --once  # init convex/_generated/, ask deployment URL via OAuth
```

Output: cartella `convex/` con schema vuoto + `.env.local` con `NEXT_PUBLIC_CONVEX_URL`.

#### Step 1.3 — Scaffold provider chain

File: `app/ConvexClientProvider.tsx`

```typescript
"use client";
import { ConvexReactClient } from "convex/react";
import { ConvexProviderWithClerk } from "convex/react-clerk";
import { ClerkProvider, useAuth } from "@clerk/nextjs";

const convex = new ConvexReactClient(process.env.NEXT_PUBLIC_CONVEX_URL!);

export function ConvexClientProvider({ children }: { children: React.ReactNode }) {
  return (
    <ClerkProvider publishableKey={process.env.NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY!}>
      <ConvexProviderWithClerk client={convex} useAuth={useAuth}>
        {children}
      </ConvexProviderWithClerk>
    </ClerkProvider>
  );
}
```

Edit `app/layout.tsx`:

```typescript
import { ConvexClientProvider } from "./ConvexClientProvider";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body><ConvexClientProvider>{children}</ConvexClientProvider></body>
    </html>
  );
}
```

#### Step 1.4 — Middleware Clerk

File: `middleware.ts`

```typescript
import { clerkMiddleware, createRouteMatcher } from "@clerk/nextjs/server";

const isProtectedRoute = createRouteMatcher(["/dashboard(.*)", "/api(.*)"]);

export default clerkMiddleware(async (auth, req) => {
  if (isProtectedRoute(req)) await auth.protect();
});

export const config = {
  matcher: ["/((?!_next|[^?]*\\.(?:html?|css|js(?!on)|jpe?g|png|webp|svg|ico|map)).*)", "/(api|trpc)(.*)"],
};
```

#### Step 1.5 — Convex schema example

File: `convex/schema.ts`

```typescript
import { defineSchema, defineTable } from "convex/server";
import { v } from "convex/values";

export default defineSchema({
  // Sync Clerk users → Convex
  users: defineTable({
    clerkId: v.string(),
    email: v.string(),
    name: v.optional(v.string()),
    imageUrl: v.optional(v.string()),
  }).index("byClerkId", ["clerkId"]),

  // Example domain entity (rinomina per il tuo use case)
  items: defineTable({
    userId: v.id("users"),
    title: v.string(),
    completed: v.boolean(),
  }).index("byUser", ["userId"]),
});
```

#### Step 1.6 — Protected route example

File: `app/(dashboard)/dashboard/page.tsx`

```typescript
import { auth } from "@clerk/nextjs/server";

export default async function DashboardPage() {
  const { userId } = await auth();
  return <div className="p-8">Hello user {userId}</div>;
}
```

#### Step 1.7 — Update .env.local.example

```
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_xxx
CLERK_SECRET_KEY=sk_test_xxx
NEXT_PUBLIC_CONVEX_URL=https://your-deployment.convex.cloud
```

### Branch 2 — Supabase override

**Trigger**: `db_provider == "supabase"` (auth può essere Clerk o Supabase Auth)

#### Step 2.1 — Install packages

```bash
npm install @supabase/supabase-js @supabase/ssr
```

#### Step 2.2 — Scaffold client + server helpers

File: `lib/supabase/client.ts`
```typescript
import { createBrowserClient } from "@supabase/ssr";

export function createClient() {
  return createBrowserClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
  );
}
```

File: `lib/supabase/server.ts` (cookie-based server client per App Router)

#### Step 2.3 — RLS policy template

File: `supabase/migrations/0001_init.sql`
```sql
create table public.items (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users not null,
  title text not null,
  created_at timestamptz default now()
);

alter table public.items enable row level security;

create policy "users see own items"
  on public.items for select
  using (auth.uid() = user_id);
```

#### Step 2.4 — env vars

```
NEXT_PUBLIC_SUPABASE_URL=https://xxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJxxx
SUPABASE_SERVICE_ROLE_KEY=eyJxxx  # server-only
```

### Branch 3 — WorkOS enterprise

**Trigger**: `auth_provider == "workos"`

```bash
npm install @workos-inc/authkit-nextjs
```

Scaffold middleware AuthKit + callback route + provider. Note: complex, esp config WorkOS dashboard manuale.

### Branch 4 — Auth-only or DB-only

- `auth: clerk` + `db: none`: scaffold solo Clerk middleware + provider, skip Convex
- `auth: none` + `db: convex`: scaffold solo Convex (no auth), skip middleware
- `auth: none` + `db: none`: skip skill completamente, NOP

### Branch 5 — Custom auth (Q5="Già ho provider")

Ask utente quale provider (Auth0, Firebase Auth, custom). Genera adapter scaffold base + lista env vars dinamicamente.

## Edge cases

- **Clerk app non ancora creata**: instruction step-by-step screenshot per creare app su dashboard.clerk.com. Open URL in browser via Bash `open <URL>` (macOS) o `xdg-open` (Linux).
- **Convex deployment fail**: re-run `npx convex dev`, check `~/.convex/auth` per OAuth token.
- **Supabase + Clerk hybrid** (Q5=Clerk + Q6=Supabase): scaffold both, plus integration template Clerk→Supabase JWT pattern (third-party reference).

## Gotchas

- 🔴 **Convex requires browser OAuth**: `npx convex dev` apre browser per login. Audience non-dev può essere confuso. Spiega step.
- 🔴 **Clerk webhook for user sync**: per sync Clerk users → Convex `users` table, serve webhook su `app/api/webhook/clerk/route.ts`. Genera template solo se utente conferma "voglio user persistence".
- 🟡 **Middleware matcher**: il regex matcher Clerk può escludere troppo (file statici). Test che `/_next/*` sia skip ma `/api/*` sia protected.
- 🟢 **Schema iterabile**: utente può modificare `convex/schema.ts` post-scaffold, Convex auto-redeploys via `npx convex dev`.
