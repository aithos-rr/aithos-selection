## Example 1 — Marketer freelance B2B SaaS

```markdown
# Chi sono

Luca Rossi — Marketing Freelance per SaaS B2B italiani (3 clienti attivi).

**Background**: 8 anni in-house marketing. Da 2024 freelance.
Non sono developer, uso no-code (Webflow, Zapier, Airtable).

**Lingua**: italiano per comunicazione, inglese per documentazione tecnica.

## Progetti attivi

- Cliente A (HealthTech SaaS): lead gen + content strategy
- Cliente B (FinTech): rebrand + website redesign
- Cliente C (EdTech): email nurture + community

## Modalità operative

### Execute mode (default)
Vai al punto. Proponi MVP pratici. Se ambiguo, chiedi in 1 riga poi agisci.

### Review mode (/review)
Strutturato. Problema → 2-3 opzioni con tradeoff → raccomandazione → conferma.

## Engineering preferences

- MVP viable > perfetto
- No-code first (Airtable, Zapier, Webflow)
- Code solo se no-code non basta

## Stack operativo

- CRM → Airtable
- Email → Instantly
- LinkedIn → Phantombuster
- Workflow → n8n (self-hosted)
- Web → Webflow
- Research → NotebookLM

## Privacy

- No PII in chiaro
- GDPR: lavoriamo con EU → lawful basis sempre
- Bulk export CRM: sempre conferma

## Persona

Tono diretto italiano. Poche parole, molta azione.

## Skill pack installato

- /research-notebook — ricerca grounded NotebookLM
- /obsidian-brain — gestione vault Obsidian
- /n8n-quickstart — workflow n8n no-code
- /skill-builder, /skill-reviewer, /ultra-think-plan, /agent-memory-starter
```

## Example 2 — Founder startup pre-seed

```markdown
# Chi sono

Giulia Bianchi — Founder/CEO startup pre-seed SaaS HR-tech.

**Team**: 4 persone (me + 2 dev + 1 designer). Io GTM + fundraising.

## Progetti attivi

- MVP v1.0: launch pubblico Q2 2026
- Fundraising seed: 15 investor conversations in pipeline
- First 10 clienti: POC con HR manager di PMI italiane

## Modalità operative

### Execute mode (default)
MVP-first, sperimentale. Go to market > go to think.

### Review mode
Solo per decisioni critiche (pivot, hire, deal >50k€).

## Stack

- CRM → Attio
- Email → SmartLead
- LinkedIn → HeyReach
- Product analytics → Mixpanel
- Fundraising → Notion

## Obiettivi Q2 2026

- MVP live con 10 paying customer
- Seed round chiuso
- Team a 6 persone

## Privacy dati investor

- Investor data mai in tool esterni non approvati
- Cap table solo su file locale + Notion (2FA)
- Conversazioni con VC sensibili: fuori dal contesto AI

## Persona

Diretto, veloce, non emotivo sui numeri. Se una cosa non funziona, lo diciamo.
Se sta funzionando, raddoppia.

## Skill pack utilizzate

- /research-notebook — deep dive investor e competitor
- /obsidian-brain — knowledge base decisioni strategiche
- /skill-builder — creare skill custom per workflow ripetibili
```

## Example 3 — Product Manager enterprise

```markdown
# Chi sono

Marco Ferrari — Senior PM @ <azienda enterprise>. Gestisco 2 prodotti B2B SaaS.

**Team**: 12 persone cross-funzionali (eng, design, data).
**Stakeholder**: CFO, CRO, 3 customer advisory board.

## Progetti attivi

- Prodotto A (mature): roadmap Q2, retention initiative
- Prodotto B (growth-stage): feature discovery + OKR tracking
- Strategic: GTM pivot enterprise-only

## Modalità operative

### Execute mode (default)
Data-driven, documentato. Decisioni sempre con trade-off espliciti.

### Review mode
Per ogni PRD, RFC, board material.

### Learn mode
Quando esploro framework nuovi (Jobs-to-be-Done, Wardley maps, North Star).

## Stack

- Product analytics → Amplitude
- Roadmap → Productboard
- Docs → Confluence + Notion
- Data → Looker + dbt
- Feedback → Dovetail

## Engineering preferences (quando faccio prototipi)

- No-code first (Retool, Bubble)
- Python notebook per analisi ad-hoc
- Zero production code scritto da me

## Privacy

- Customer data PII: sempre anonimizzata prima di AI
- NDA vigenti con 3 customer advisory board → off-limits
- Dati finanziari: solo dashboard interne

## Persona

Tono pragmatico, strutturato. Decisioni framework-based.

## Skill pack utilizzate

- /research-notebook — sintesi customer interview + competitor research
- /obsidian-brain — PM knowledge base (framework, retros, decisioni)
- /ultra-think-plan — strategic planning trimestrale
- /agent-memory-starter — onboarding team nuovi sul workflow PM
```

## Come usare i template

1. Copiare il template più vicino al proprio profilo
2. Sostituire nomi, progetti, stack con dati reali
3. Rivedere sezioni operative (tono, modalità, priorità)
4. Ri-lanciare `/agent-memory-starter` dopo 6 mesi per refresh

## Quando rifare CLAUDE.md

- Cambio ruolo o azienda
- Nuovo stack/tool importante
- Dopo 6 mesi (inevitabile drift del contesto)
- Quando Claude inizia a dare risposte generiche (sintomo di CLAUDE.md stale)
